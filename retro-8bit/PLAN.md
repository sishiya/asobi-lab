# 8ビット互換機（ファミコン互換エミュレータ）とオリジナルのソフト — 企画書

2026-10-24〜。ユーザー「まずは練習がてらファミコン互換エミュレータと、１本オリジナルゲームを作って」。

## 0. 方針（ライセンス）
- **エミュレータは一から自分で書く**（ほかのエミュレータのコードは使わない）。CPU（6502）・PPU（絵）・APU（音）・カートリッジ（マッパー 0・1・2・3・7、v028 で 4＝MMC3 も、v029 でおもなもの 41 種に）。
- **BIOS はない機種なので、メーカーのコードは1バイトも入れない**。色の表（パレット）は数で決める。
- **市販ソフトは入れない・リンクしない**。
- **自分のファイルを開く**（2026-10-24 ユーザー「アップロードして起動できるように」で v002 から）: **この端末の中だけで読み、どこにも送らない**（サーバーに上げる作りにはしない）。v007 から、開いたファイルを**このブラウザの IndexedDB にだけ**残す（ユーザー「じぶんのカセットは保存されて削除や名前変更が自由にできるといい」。ほかの人と分けない・同期しない・遊ぶ人が自分で選んだときだけ・なまえを変える／すてるは自由・30本まで）。「権利を持っているファイルだけ」と書く。市販ゲームの名前・画面・動作の一覧・ROM サイトへのリンクは出さない。市販ゲームで遊べることを宣伝しない。
- 棚の ROM（あそびラボのオリジナル）は自由にダウンロードできる（中身は CC BY-NC 4.0）。
- エミュレータの検証に市販 ROM は使わない。使うなら、エミュレータ検証用に配られているテスト ROM（nestest・blargg のテストなど）を、ユーザーの OK をもらってから手元だけ（`_dev/`）で。
- **商標を名前に使わない**: 画面・タイトル・ファイル名に「ファミコン」「NES」「任天堂」は出さない（このメモと DEVNOTES の説明だけ）。呼び名は「8ビット互換機」。
- 入れるソフトは**あそびラボが作ったものだけ**（ソースもこのフォルダ。アセンブラも自作）。

## 1. 何を作るか
1. **エミュレータ**（`js/`）: ブラウザで動く。キーボード・ゲームパッド・スマホの指。音は WebAudio。
2. **アセンブラとビルド**（`tools/`）: 6502 のアセンブリ（`src/<ゲーム>/game.s`）と、文字で描いたドット絵（`src/<ゲーム>/art.mjs`）から `.nes` を作る。
3. **オリジナルゲーム**: 「カエルのよる」（`src/frog-night/` → `roms/frog-night.nes`）、「恐竜かけっこ牧場 8bit」（`src/dino-ranch/` → `roms/dino-ranch.nes`。v002）、「ダンゴムシのみち」（`src/pillbug-path/` → `roms/pillbug-path.nes`。v015）。

## 2. カエルのよる（手ざわり）
- 夜の池。カエルが下のハスの葉の上を **左右に動き**、**A で舌を真上にのばす**。のびる → もどる、の1往復。
- 飛んでいる虫を舌の先でとる。1回ののびで何匹もとるとボーナス（×2・×3…）。
  - ハエ 10点（速い）・ガ 30点（ゆっくり大きくゆれる）。
  - **ホタルは食べてはいけない**（ホタルは体に毒をもち、食べた生き物は具合が悪くなる。本物のしくみ）。とるとハートが1つ減り、カエルはしばらく目を回す。光っていて目立つ＝いちばん目に入る物が、さわってはいけない物。
- 夜は 90 秒。だんだん虫が増え、ホタルも増える。空が少しずつ明るくなり、朝で終わり。ハート3つがなくなっても終わり。
- 操作: ←→ 移動、A（X キー）舌、START（Enter）はじめる・一時停止。

## 3. 段階
- 段階A（v001）: エミュレータ＋カエルのよる1本、保管庫に置く。
- v002（2026-10-24）: トップを棚に・ファイルを開く・ダウンロード。**恐竜かけっこ牧場 8bit**（dino-race の移植。ユーザー「恐竜・ぺらぺら・箱庭のうち1つ以上を 8bit 版に」→ 芯が数と表に移しやすい恐竜を選んだ。ぺらぺら（3D の断面）と箱庭（水の計算）は、この機械の力では芯が残りにくい）。ブラウン管の画面（ユーザー「ブラウン管のドット絵アプリから移植してブラウン管をエミュレートできるように」）。

## 4. やらないこと（いまは）
- 市販ソフトの動作の保証、DMC の音、PAL、MMC5 の画面の分割と音、バンダイの EEPROM のセーブ、ディスクの機械。（MMC3 は v028、ほかのおもなマッパーは v029 で入れた。ユーザー「メジャーどころで対応していないものがあれば」）

## 5. 恐竜かけっこ牧場 8bit（v002）
- もとの芯をのこす: 2頭をえらんでかけ合わせ → 卵3つ → 1頭を残す（牧場は4頭）。100m のかけっこ。大きい体は重く筋肉が足りない（Hutchinson & Garcia 2002 の考え方）。脚が長く足が速いほど転びやすく、しっぽでつり合い。見た目は図鑑の骨格図（クリームの紙にインクの骨）。
- 物理のかわりに式（`src/dino-ranch/data.mjs` の `derive`、ROM の `derive` と同じ）: 出したい速さ = 18＋脚＋足の速さ＋大きさ/2、筋肉で出せる速さ = 26＋筋肉×2−大きさ×1.5 の小さい方（km/h）。転びやすさ = 脚＋足の速さ＋大きさ/2 が 10＋しっぽ×2 をこえた分。転びやすい子には「WOBBLY」。
- 杯3つ×3回。ライバルは 22〜46 km/h（1回目 22・24・26 から、3杯目の最後 42・44・46）。1位でつぎへ。ぜんぶ勝つとエンディング（Sellers & Manning 2007 にふれる）。
- スタートの「GO!」のすぐあとに A でよいスタート、GO の前に押すとフライング（小さな遊び。もとにはない）。
- 難しさ: 同じ決まりの JS のシミュレーション（いちばん速い2頭をかけ合わせ、いちばんよい子を残すだけの手）で、3杯まで 15〜30 世代。変わる確率を 1/4 → 1/2、3杯目のライバルを 2 km/h 下げてこうした。

## 6. ダンゴムシのみち（v015）
- 2026-10-25 ユーザー「8bit アプリをもう一つふやして。ジャンルがかぶらないほうがいいかな。カエルのよるは意外と淡々とシンプルルールで楽しめるので良かった」。カエル＝アクション、恐竜＝育成とレースなので、**パズル**。決まりは1つだけで、あとは見ていれば分かる、淡々と遊べるもの。
- 手本の本物: **ダンゴムシの交替性転向反応**（ふさがれて左に曲がると、つぎの分かれ道では右に曲がりやすい。左・右・左…とジグザグになり、ふさいだものから一つの向きへ離れていける、という考え）。
- 決まり: 16×12 のます。ダンゴムシは前がふさがれたとき（岩・置いた石・面のふち）だけ曲がる。曲がる向きは前の曲がりと逆（はじめは左）。その向きがふさがっていれば逆へ（このときはつぎの向きは変わらない）、両方だめなら引き返す。葉っぱを全部食べるとクリア。ひなたに入ると丸くなって、やりなおし（ダンゴムシは乾くのが苦手で、明るいところをさける）。
- 遊び方: 先に石を置き（A で置く・とる、SELECT で全部もどす）、START で歩かせて見る。歩いているあいだは見るだけ（A を押しているとはやく、B で止めて石を置きなおす。石はそのまま）。**つぎに曲がる向きを、ダンゴムシの横の矢じるしで見せる**（決まりが見て分かるように）。
- 12 面: 1面は石なしで「左・右」を見るだけ、2〜6面は石1つ（右へ曲げる・ふさがれて逆へ・葉っぱ2枚・ひなた）、7〜10面は石2つで解ける（1つゆとりを足して3つ置ける。2つで解くと BEST）、11・12面は石3つ。7面からは候補を道具で作り（`tools/pillbug-levels.mjs --gen`）、解の数と歩く長さで選んだ。
- セーブ（電池）: どこまで進んだか。タイトルで ←→ で、とどいた面をえらべる。最後にエンディングで本物のしくみにふれる。


## 8. 基板をのぞく（2026-10-25〜）
- ユーザー「ゲーム中に基板の様子も見れるようにして、いまどこの部品が働いていてどんな通信が行われているのか、機械の中の様子が見れると面白い」「Linux 互換機をつくるより、そちらを先に」「動作をかなりゆっくりにしつつ基板の中の動きを見るモード」。
- **芯**: ボタンを押してから画面と音が変わるまでが、部品の順に見える。8ビットの機械は部品が少なく役わりが分かれているので、部品の動きとゲームの出来事が1対1でつながる（Linux 機だと CPU とメモリがずっと光るだけになる）。「いま光れ」（ビームのタイミング）の兄弟。
- **手ざわり**: 遊ぶ画面の上の「基板」を押すと、画面の横（スマホは下）に本体の中の図が出る。速さを ふつう・1/10・1/100・1/1000・止める から選ぶ。止めたら「1命令」「1こま」で進める。遊びはそのまま続けられる（ゆっくりでもボタンは効く）。
  - 部品（チップ）は、働いた量だけ光る。部品をつなぐ線（CPU の線・絵の係の線・合図の線）も、通ったぶんだけ光る。
  - ゆっくりのときは、目立つ出来事（ボタンを読む・キャラの位置をまとめて送る・描き終わりの合図・音を変える・ROM の切りかえ・セーブ）を、線の上を走る粒と、図の下の一行の説明で見せる。一度に見せる説明は1つ（RULES 4章）。
  - 画面には、いまビームが描いているところに光る点を出す（ゆっくりのとき）。
  - ゆっくりのあいだは音を止める（音の係が働いているのは図で見せる）。
- **基板の図はあそびラボの絵**: 本物の基板の写真・配置・型番の写しは使わない。部品の役わりがひと目でわかる図（CPU＋音・作業メモリ・絵の係・画面の表のメモリ・カセットの プログラムの ROM／絵の ROM／マッパー／電池のメモリ・コントローラーの口・テレビへの口）。カセットの中身は、さしたソフトに合わせて出し分ける。
- **段階**:
  - 段階A（v031）: 基板の図・部品と線の光・速さの切りかえ・1命令／1こま・ビームの点・目立つ出来事の粒と説明。
  - 段階B: 3D の部屋で本体のふたを開ける（v032。ユーザー「本体の蓋をあけたい」）。ほかは未定:「ボタン1回を追う」（押した瞬間から、読む → 計算 → 送る → 描く → 鳴る を自動でゆっくり追う）・部品を押すと中身（メモリの中・絵の ROM の絵・音の波）が見える。
